# Architectural decisions

Read the accepted records before changing consequential behavior. For a new decision, add the next numbered Markdown file with **Status, Context, Decision, Consequences, Verification**. Link affected code and evidence. Keep old records; supersede them explicitly rather than rewriting history. Routine refactors and tuning inside delegated boundaries do not need owner approval. A changed product direction, acceptance budget or new service spending does.
