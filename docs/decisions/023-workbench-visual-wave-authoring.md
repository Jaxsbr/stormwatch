# 023 — Visual wave authoring

## Context

The owner found the task-oriented second workbench substantially clearer but still too demanding to use. Its preview was the most helpful element. They requested a third iteration in which manipulation of groups, batches and cycles generates configuration, with enemy imagery replacing text-only selection. Independent Astra and Claude Opus 5.5 reviews carried the earlier first-use and edit-integrity criteria into this iteration.

## Decision

Make the arrival timeline the primary authoring surface. Species rows are visual guides for one ordered schedule. Selecting a group exposes its local controls and handles; moving it changes its preceding wait and shifts subsequent arrivals. Its extent includes final batch spacing, with the trailing portion distinguished from actual arrivals. Count is a separate control. A local batch view supports uniform staggering and spacing. Sequences show linked repeated copies and disclose that edits affect every copy.

Use immutable, validated recipe edits and the existing compiler and spawn scheduler. The canvas is a browser adapter; gameplay and canonical tuning remain unchanged. Reuse existing enemy body artwork. Keep encounter resources, catalogs, technical recipes and effective-value inspection available through disclosures. Keep testing and experiment management intact.

## Consequences

Designers can shape release rhythm spatially and undo accepted edits. There are no independently placed enemy tracks, overlapping groups or individually editable linked repeats. Hand-unrolled content remains hand-unrolled; the editor does not silently rewrite it as a repeated pattern. Guard, evasion and movement remain precise configuration properties rather than spatial placement rules.

The visual model maintains explicit timing limits and rejects invalid proposals. Expert recipe changes refresh the same canvas; invalid external input is retained and pauses visual editing so a stale canvas cannot overwrite it. Saved drafts and production progression remain separate.

## Verification

Focused model tests compare layouts and edits against the shared compiler and scheduler, including repeat rest, trailing spacing, partial batches and invalid transitions. Browser verification covers direct manipulation, selection, undo, linked repeats, save/play and narrow layouts. The iteration report records matched captures, required checks and remaining limits. Expert review and viewport emulation do not establish owner acceptance or physical-device performance.
